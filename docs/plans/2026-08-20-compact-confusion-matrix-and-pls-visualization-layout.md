# 混淆矩阵 PNG 与 PLS-DA 可视化布局修正计划

## 目标与成功标准

在不改变训练指标、模型计算和 `run-result-v1` 数据契约的前提下，修正本轮新增可视化的导出与页面布局：

1. 混淆矩阵 PNG 只保留类别坐标和矩阵网格，删除标题、Run/评估口径说明、底部统计说明以及由这些内容造成的大面积留白；矩阵连同坐标在画布中紧凑居中。
2. PLS-DA 的三张图在桌面宽屏下同一行展示，图表尺寸明显缩小但文字仍可读；中等宽度自动变为两列，窄屏自动变为一列。
3. PLS-DA 潜变量得分图完整显示全部样本点和完整 95% 置信椭圆，不再发生椭圆被坐标范围裁切或图形藏在横向滚动区中的情况。
4. 最终必须使用真实网站和真实 PLS-DA Run 完成人工视觉验收：分别截取混淆矩阵页面区域、三张模型特征图同屏区域，并实际下载、打开一张混淆矩阵 PNG 检查裁切和居中。

## 已确认的问题与实现边界

- 当前 PNG 导出器在矩阵上方预留标题和列标签区，在下方预留统计说明区，并绘制 Run ID、评估口径与颜色解释；这些内容全部移除。
- “只保留混淆矩阵”解释为保留矩阵单元格、数值、行类别标签和列类别标签。否则无法判断真实类别与预测类别。页面上的下载按钮和页面卡片标题仍保留，不进入 PNG。
- 当前 PLS-DA Run `5145cd90328b41c5874241a400c8fa05` 的得分图包含 72 个点，数据没有丢失。问题来自前端坐标域只使用样本点：样本点 X 范围约 `-59.83..143.43`，95% 椭圆 X 范围约 `-121.08..121.08`，椭圆左侧必然被裁切；Y 轴也存在相同问题。
- 当前 `.model-feature-chart` 固定 `min-width: 620px`，而容器使用两列网格；桌面端卡片过高，较窄卡片还会出现内部横向滚动。修正应优先响应式缩放，不依赖横向滚动才能看到完整图。
- 本次不修改 PLS-DA 训练、VIP 算法、置换检验算法、Manifest 或结果接口结构，也不重新生成历史 Run。前端修正应能直接正确显示现有 Run。
- 同一共享 SVG 渲染器被经典页面和 v2 页面消费；布局规则需同步覆盖两个入口，不能只修截图中的经典页面。

## 任务 1：把混淆矩阵 PNG 改为紧凑居中导出

**实施内容：**

- 删除 `titleHeight`、`footerHeight` 以及与标题、Run、评估口径、统计句相关的绘制逻辑。
- 画布尺寸只由以下部分组成：统一外边距、左侧行标签宽度、顶部列标签高度、矩阵网格尺寸。
- 根据最长类别名动态计算行/列标签空间；列标签仍允许旋转，但必须完整落在画布内。
- 让“行标签 + 列标签 + 网格”作为一个整体在画布中水平、垂直居中，四周只保留小而一致的安全边距。
- 保持 2 倍像素导出、白底、对角线/误分类配色、文件名清洗和 Train/Valid/Test 分区命名不变。

**验收标准：**

- PNG 中不出现“Train/Valid/Test 混淆矩阵”、Run ID、评估口径、“行是真实类别”等说明文字和底部样本统计。
- PNG 中只有类别标签、矩阵单元格和数值；网格不会偏向右下角，也没有明显无用途白边。
- 4 类和长类别名用例均不截断矩阵或坐标标签。

**自动验证：**

- 更新纯函数断言，检查布局结果不再包含标题/页脚空间，网格四周边距处于预期范围。
- 继续验证危险 Run ID 清洗、分区文件名和非法矩阵降级。

## 任务 2：修复 PLS-DA 得分图完整性

**实施内容：**

- `scatterPlot()` 计算 X/Y 坐标域时，合并全部有效样本点坐标与 `ellipse.points`，再统一增加约 6%–10% 安全边距。
- 过滤置信椭圆中的非有限值；椭圆无效时只降级为样本点散点图，不影响其他两张图。
- 确保完整椭圆、所有 72 个样本点、零轴、轴标题和图例都在 SVG `viewBox` 内。
- 保留颜色=真实类别、形状=Train/Valid/Test 的语义；不改变后端坐标或重新拟合 PLS。
- 在紧凑尺寸下缩短轴边距并保持鼠标悬停信息，避免为了缩小卡片而删掉可审计信息。

**验收标准：**

- 对真实 Run 的数据范围，椭圆最左/最右/最高/最低点均在绘图区内，不触碰或越过 SVG 边界。
- 72 个有效样本点仍全部生成标记；图例能同时说明四个类别和三个数据分区。
- 得分图无需水平滚动即可看到完整主体。

**自动验证：**

- 为“椭圆范围大于样本点范围”增加前端纯函数或可检查的坐标域测试，断言最终坐标域覆盖两者。
- 保留未知图形类型和无有效坐标的降级测试。

## 任务 3：把 PLS 三图改成紧凑响应式布局

**实施内容：**

- 桌面宽屏使用 `repeat(3, minmax(0, 1fr))`，让得分图、VIP、置换检验按产物顺序位于同一行。
- 中等宽度使用两列，第三张图自然换行；窄屏使用一列。
- 移除通用图表 `min-width: 620px`，改为 `width: 100%; min-width: 0`；SVG 依靠 `viewBox` 等比缩放。
- 将散点图和置换检验的基础 `viewBox` 调整为更适合三列卡片的横纵比；VIP 在紧凑宽度下减少默认展示项或使用更紧凑标签策略，但完整 VIP 仍保留在 JSON 下载产物中。
- 压缩卡片内边距、说明文字和图例间距，同时设定最低可读字体，不把三个图缩成无法辨认的缩略图。
- 同步经典页面与 v2 页面断点，避免两个入口布局不一致。

**验收标准：**

- 约 1920px 桌面视口下三张图同一行、卡片等宽、无横向滚动条。
- 约 1200px 视口下允许两列，约 768px 以下为单列；任何断点均不溢出结果页。
- 三图标题、坐标、图例和关键说明可读，页面高度显著低于当前两列大图布局。

## 风险与回退

- 类别名过长时，紧凑 PNG 可能被标签宽度主导。默认优先保证标签完整，再限制最大画布宽度；如超过限制，使用可预测的省略号而不是裁切矩阵。
- 三列布局会缩小 VIP 横轴标签。默认以减少页面展示项、保留完整 JSON 下载作为平衡，不改变 VIP 值本身。
- 置信椭圆可能远大于样本点云，纳入坐标域后会压缩点云。默认保证完整性优先；若真实截图显示点云过度压缩，再考虑为椭圆设置明确的可视化提示或单独开关，不能静默裁掉椭圆。
- 如视觉验收不通过，只回退布局/CSS/坐标域相关改动，不回退已完成的模型产物与下载能力。
