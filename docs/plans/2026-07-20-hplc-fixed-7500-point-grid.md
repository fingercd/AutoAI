# HPLC 固定 0–50 分钟、7500 点线性映射实施计划

> 实施变更（根据后续确认）：保留前端范围选择与插值开关。开启插值时，范围选择固定完整轴的对应切片（例如 1–4000 行输出前 4000 个固定目标点），并使用完整源曲线计算强度；关闭时导出所选原始 X/Y。本文后续“删除范围/开关”和“始终输出完整 7500 点”的原始条目已被本说明取代。

## 1. 目标与结论

把正式 HPLC 预处理收敛为一个不可变的数据契约：每个输入文件必须包含 **7500 个有效色谱点**，输出统一使用 **0–50 分钟、包含首尾端点的 7500 点固定时间轴**，每个目标时间点的强度由原始时间轴上包围它的相邻两点做分段线性插值。

本方案不再从上传文件推断共同 X 轴，也不再允许关闭线性映射。输入 `XXX` 只负责确定插值时的左右邻点，不能改变输出 `XXX`；减最小值消负和面积归一化继续保持删除状态。

## 2. 已确认需求与成功标准

### 2.1 已确认需求

- 数据类型是 HPLC 色谱。
- 时间单位固定为分钟。
- 正式 HPLC 输入每个文件必须恰好解析出 7500 个有效数值点；7499、7501 或其他点数都直接报错，不补点、不删点、不降采样。
- 输出时间范围固定为 0–50 分钟。
- 输出 `XXX` 与任何单个输入文件的 `XXX` 数值无关，同一批及不同批次都生成完全相同的固定轴。
- 输出强度不按点号直接搬运，而是在原始 X 轴上找到目标时间左右相邻的两个点，再做线性插值。
- 不执行消除负值、面积归一化或其他强度变换。

### 2.2 成功标准

1. 任意成功生成的 HPLC 样本在建模读取后都满足：`len(XXX) == len(Intensity) == 7500`。
2. 每个样本读取后的 `XXX` 完全一致，首点为 `0.0`、末点为 `50.0`。
3. 固定轴第 `j` 个点严格按 `x[j] = j * 50 / 7499` 生成，其中 `j = 0..7499`。
4. 固定步长为 `50 / 7499 ≈ 0.00666755567409` 分钟，约 `0.400053340445` 秒。
5. 输入点数不为 7500、X 轴非严格递增、存在重复 X、包含非有限值，或不能覆盖 0–50 分钟时，整批请求返回明确的 400 错误，并指出文件名和原因。
6. 计算过程中使用 `float64`；只有写入最终 CSV 时才按现有 Excel 安全策略选择最高可容纳的强度小数精度，不在插值前提前舍入。
7. 固定 X 轴不得因 Excel 单元格限制被舍入成重复坐标，也不得静默截断。
8. 经典前端和 v2 前端不再显示范围选择或“是否插值”开关，而是明确显示固定处理规则。
9. 既有拉曼流程和兼容接口 `/api/preprocess/chromatography` 不受影响。

## 3. 固定轴与强度算法

### 3.1 固定目标轴

采用包含 0 和 50 两个端点的约定：

```text
TARGET_START_MINUTES = 0.0
TARGET_STOP_MINUTES  = 50.0
TARGET_POINT_COUNT   = 7500
target_x[j] = TARGET_START_MINUTES
              + j * (TARGET_STOP_MINUTES - TARGET_START_MINUTES)
                    / (TARGET_POINT_COUNT - 1)
```

实现使用 `np.linspace(0.0, 50.0, 7500, dtype=np.float64)`。虽然用户接受 `50/7500` 和 `50/7499` 两种定义，本计划选择 `50/7499`，原因是它同时满足“恰好 7500 点”和“实际覆盖完整 0–50 分钟（含首尾）”，验收条件也更明确。

### 3.2 输入校验顺序

每个文件按以下顺序处理，任一失败立即中止整批生成：

1. 读取前两列可解析数值，表头不计入数据点。
2. 统计有效 `(x, y)` 对，必须恰好为 7500。
3. 校验 X、Y 均为有限数值，不允许 `NaN`、`+Inf` 或 `-Inf`。
4. 校验 X 严格递增，即所有 `x[i + 1] - x[i] > 0`；重复点和倒序点均报错，不自动排序，因为自动排序可能掩盖采集顺序问题。
5. 校验源 X 轴覆盖目标区间 `[0, 50]`，禁止依赖 `np.interp` 的端点常数填充来伪装外推。
6. 设置一个很小的端点容差（建议 `1e-8` 分钟）：只对与 0 或 50 的浮点读写微小误差做吸附；超过容差且不能覆盖完整区间就报错。

建议的错误信息格式：

```text
sample_03.csv 解析到 7499 个有效色谱点，HPLC 固定流程要求恰好 7500 个点；未生成任何结果文件。
sample_06.csv 的时间轴在第 218、219 个点重复（12.345 分钟），要求严格递增；未生成任何结果文件。
sample_08.csv 的时间范围为 0.2–49.8 分钟，不能覆盖固定目标范围 0–50 分钟；禁止外推。
```

### 3.3 如何选择“哪两个相邻点”

对每个固定目标点 `t = target_x[j]`：

1. 在源 X 轴上用二分查找找到插入位置 `k = searchsorted(source_x, t, side="left")`。
2. 若 `source_x[k] == t`，直接使用 `source_y[k]`，避免本来已有准确采样点却再次计算。
3. 否则选择 `i = k - 1`，使用唯一满足 `source_x[i] < t < source_x[i + 1]` 的左右相邻点。
4. 按下式计算目标强度：

```text
target_y[j] = source_y[i]
              + (t - source_x[i]) / (source_x[i + 1] - source_x[i])
                * (source_y[i + 1] - source_y[i])
```

完成严格递增和覆盖范围校验后，可在生产代码中使用等价且向量化的 `np.interp(target_x, source_x, source_y)`；单元测试必须用上面的手算公式独立核对，不能只测试函数“能运行”。

示例：源相邻点为 `(0.000 分钟, 100)` 和 `(0.010 分钟, 130)`，固定轴第二个点为 `50/7499 ≈ 0.0066675557` 分钟，则：

```text
目标强度 = 100 + (0.0066675557 - 0) / (0.010 - 0) * (130 - 100)
         ≈ 120.002667
```

这里选择的是包围目标时间 `0.0066675557` 的两个相邻源点，不是按数组下标机械选择同号点。

## 4. Excel 单元格上限与 `XXX` 表示

### 4.1 必须解决的问题

7500 个 0–50 分钟的高精度 X 值如果继续作为完整 JSON 数组写入一个 CSV 单元格，通常会超过 Excel 的 32,767 字符上限。继续降低 `XXX` 小数位虽然能缩短文本，但步长仅约 0.00667 分钟，精度降低后会产生大量重复坐标，违反固定准确轴和严格递增要求。

因此，HPLC 的固定轴不能继续走普通数组的“降精度以塞进单元格”路径。

### 4.2 采用紧凑、可逆的固定轴描述

保持六列建模 CSV 不变：`Index, Name, XXX, Intensity, Label, Sample_ID`。新 HPLC 文件的 `XXX` 写入短 JSON 描述，而不是重复写 7500 个数值：

```json
{"type":"linspace-v1","start":0,"stop":50,"count":7500,"unit":"minute"}
```

读取建模 CSV 时：

- 普通列表/元组仍按既有逻辑读取，确保旧拉曼和旧建模 CSV 兼容。
- 仅 `XXX` 允许识别严格白名单的 `linspace-v1` 描述；`Intensity` 仍必须是非空数值数组。
- 校验描述字段、类型、有限值、`count` 上限和 HPLC 固定契约后，用 `float64 np.linspace` 恢复为 7500 个 X 值。
- 描述无法识别或参数非法时明确报错，不能猜测。

这样 Excel 中 `XXX` 单元格只有几十个字符，但训练、预览和建模摘要读取到的仍是准确的 7500 点数值轴。

### 4.3 强度序列化

`Intensity` 仍包含每个目标点的实际数值，无法像固定轴一样用公式描述。继续使用已经实现的批次统一自适应精度算法：

1. 先以 `float64` 完成所有插值。
2. 从最多 5 位小数开始，逐级尝试到 0 位。
3. 选择整批所有样本都不超过 32,767 字符的最高统一精度。
4. 若即使 0 位仍超过上限，或降低精度会抹掉全部有效变化，则直接报错，不截断、不降采样。
5. API 返回最终 `Intensity` 小数位和最长单元格字符数；HPLC 的 `XXX` 元数据改为 `axis_encoding=linspace-v1`，不再显示误导性的 `xxx_decimal_places`。

- `x_axis_consistent`、关闭插值产生的 `warnings`、`hplc_interpolate` 响应字段和动态 `common_time_path` 进入删除清单；固定轴已经天然一致，不再生成重复 `.npy` 文件。

## 7. 分阶段实施任务

### 阶段 A：锁定纯算法和不变量

1. 在 `backend/app/hplc.py` 定义固定常量和 `build_hplc_target_axis()`。
2. 实现单文件校验函数，统一返回文件名明确的错误。
3. 实现 `map_hplc_intensity(source_x, source_y, target_x)`，在校验后调用向量化线性插值。
4. 删除 `compute_common_time_axis()` 的数据推断策略，或将其替换成无输入、只返回固定轴的函数；删除中位点数和重叠区间逻辑。
5. 让 HPLC 流程始终读取完整文件、逐文件映射到同一固定轴，并保留负值和原始幅度比例。

### 阶段 B：解决固定轴在 CSV 中的可靠表示

1. 拆分“普通数值数组解析”和“建模 X 轴解析”，确保描述符只对 `XXX` 生效。
2. 实现 `linspace-v1` 严格解析、验证和 float64 恢复。
3. HPLC 导出每行写同一个固定轴描述符，训练加载时恢复为 7500 点数组。
4. HPLC `Intensity` 继续走自适应最高安全精度；调整返回元数据和错误文案，不再建议 HPLC 缩小范围。
5. 保证旧数组形式的建模 CSV、拉曼导出和训练读取完全兼容。

### 阶段 C：收敛 API

1. 正式 HPLC 路由不再把范围参数和插值开关传给 HPLC 管线。
2. 对 HPLC 非默认范围请求返回可理解的 400；拉曼和兼容 chromatography 维持当前行为。
3. 响应加入 `hplc_axis`，`common_time` 固定为同一 7500 点轴。
4. 删除 `hplc_interpolate`、`x_axis_consistent`、关闭插值 `warnings` 和 `common_time_path`。
5. 确认错误发生时不落盘最终 CSV 或共同轴文件，避免出现半成品。

### 阶段 D：更新两套前端

1. 经典 UI 改成固定规则卡并停止提交旧字段。
2. v2 UI 改成固定规则卡并停止提交旧字段。
3. 两套 UI 都显示后端真实 `hplc_axis`，不在前端自行猜测点数或范围。
4. 两套 UI 都原样展示严格校验错误；不把 400 误写为网络错误。
5. 更新成功结果中的强度精度说明和曲线预览。

### 阶段 E：文档、迁移与清理

1. 更新项目规则、README、上下文与前后端交接契约。
2. 明确旧 HPLC 数组 CSV 仍可读取，但新 HPLC 导出统一使用 `linspace-v1`。

## 9. 风险、兼容性与回滚

### 9.1 主要风险

- **外部工具兼容性：** 新 HPLC 的 `XXX` 是可逆描述符，不再是展开数组。项目内部读取器会兼容，但绕过项目读取器、直接假设 `XXX` 必须是列表的外部脚本需要同步升级。
- **强度精度与 Excel 上限：** 固定 7500 点后，某些大整数位或高变化强度仍可能无法在单元格内安全容纳。此时必须明确失败；本任务不引入静默降采样。
- **旧前端缓存：** 部署后需要重启后端并强制刷新浏览器，避免旧页面继续发送已删除的开关或范围字段。
- **输入单位：** 本方案明确输入 X 为分钟。如果上传数据实际使用秒，严格覆盖检查可能看似通过但语义错误，因此页面、错误信息和接口文档都必须显式写“分钟”。

### 9.2 回滚方式

- 算法、解析器、路由、前端和测试作为一个改动簇提交，避免只回滚其中一层造成契约不一致。
- 回滚时恢复上一个完整改动簇；不删除已经生成的数据文件。
- `load_modeling_csv()` 对旧数组格式的兼容分支应长期保留，因此即使回滚新导出逻辑，也不会影响历史建模 CSV。
