# 预处理导出自适应最高小数精度实施计划

## 目标与成功标准

在不改变统一建模 CSV 六列契约 `Index, Name, XXX, Intensity, Label, Sample_ID`、不删点、不降采样的前提下，将当前固定保留 5 位小数的导出策略改为“在 Excel 单元格 32,767 字符上限内自动选择最高可用小数位数”。

成功标准：

- `XXX` 与 `Intensity` 分别从最多 5 位小数开始试算，选择能让本批次该字段所有样本安全写入 Excel 的最高统一精度。
- 正常短曲线继续保留最多 5 位小数，行为与当前版本兼容。
- 需要降低精度时只量化数值，不删除、重排、拆分或插值数据点；输出数组长度和点位对应关系保持不变。
- CSV 中的 `XXX`、`Intensity` 与 API 预览中的对应 `x`、`corrected_y`/`processed_y` 来自同一份量化结果。
- 后端响应和前端结果区明确显示实际采用的 `XXX`、`Intensity` 小数位数；用户能够知道系统是否降低了精度。
- 如果 0 位小数仍超过 32,767 字符，或为了满足长度限制必须把原本有变化的数据量化成常量，则返回 HTTP 400，不生成残缺 CSV。
- 下载的 CSV 仍能被 `load_modeling_csv()` 完整回读，且 Excel 打开后保持每个样本一行、固定六列。

## 关键决策

### 1. 精度按“本批次、每个字段统一”选择

- `XXX` 和 `Intensity` 独立选精度。例如 `XXX` 最终可能为 1 位，`Intensity` 为 4 位。
- 同一个批次内，同一字段的所有样本使用相同精度，而不是逐样本选择不同精度。
- HPLC 的共同时间轴天然只需计算一次 `XXX` 精度；全部处理后强度共同决定一个 `Intensity` 精度。
- 拉曼和兼容色谱即使各文件 X 轴不同，也共同选择一个 `XXX` 精度；全部校正后强度共同选择一个 `Intensity` 精度。

采用批次统一精度的原因是避免不同样本带有不同量化步长，降低模型学习到序列化/量化差异而非真实谱图差异的风险，同时保证结果可解释、可复现。

### 2. 使用有限穷举，不使用字符数比例估算或二分搜索

候选精度固定为 `5, 4, 3, 2, 1, 0`。对每个候选值生成最终实际 JSON 字符串并测量 `len(serialized)`；第一个满足全部约束的候选值就是最高可用精度。

候选只有 6 个，逐个试算开销很小，而且比根据平均字符数估算可靠。数字进位、负号、指数记法和尾随零都会使序列化长度不严格线性，因此不依赖二分搜索的单调性假设。

### 3. 长度按最终落盘文本计算

每个候选精度的处理顺序固定为：

1. 将输入转为一维 `float64` 数组。
2. 拒绝 NaN、正无穷和负无穷。
3. 使用 `np.round(array, decimals=d)` 量化，其中 `d` 为当前候选精度。
4. 把正负零统一为 `0`，避免输出 `-0.0`。
5. 将量化后为整数的值在更短时编码成 JSON 整数，避免 `123.0` 中无意义的 `.0`；非整数仍使用合法 JSON 数字。对极大整数若指数形式更短，则保留更短且数值等价的表示。
6. 使用无空格的紧凑 JSON 数组格式生成最终字符串。
7. 以最终字符串的 Python 字符数检查 `<= 32767`，不以估算值、文件字节数或压缩前中间值判断。

“保留 d 位”定义为每个普通十进制数最多保留 d 位小数，并允许删除无意义尾随零；不是强制所有值都补足 d 位。

### 4. 保留数据有效性保护

- 如果原数组存在变化，但某个候选精度量化后变成常量，该候选不可用；更低精度也不再可能恢复变化，可以直接判定精度不足。
- 若长度要求和有效变化要求无法同时满足，错误信息需包含字段名、点数、0 位精度下的实际字符数或最短字符数，并明确说明“继续降低精度会丢失有效变化，请缩小范围或改用降采样/非 Excel 格式”。
- 不增加静默截断、自动删点或自动降采样作为兜底。
- 本次沿用现有“量化后失去全部变化”判据，不额外引入主观的相对误差阈值；真实数据验收中另行比较量化误差、峰形和面积，避免把未经验证的质量阈值硬编码进接口。

### 5. 兼容性与可观察性

预处理成功响应新增以下加法字段，不删除或改名现有字段：

```json
{
  "output_precision": {
    "adaptive": true,
    "max_decimal_places": 5,
    "xxx_decimal_places": 1,
    "intensity_decimal_places": 4,
    "xxx_max_characters": 28754,
    "intensity_max_characters": 32110,
    "excel_cell_character_limit": 32767
  }
}
```

- `xxx_max_characters`、`intensity_max_characters` 是本批次最终 CSV 中对应字段的最大实际字符数。
- 前端成功结果区始终可显示采用精度；当任一字段低于 5 位时使用醒目但非错误的提示：“为兼容 Excel，本批次已自动采用 XXX 最多 N 位、Intensity 最多 M 位小数；数据点数量未改变。”
- 不向请求表单增加用户可控制的精度参数，避免用户手动选择超过 Excel 上限的值；算法始终以 5 位为上限自动求解。

## 任务 2：实现批次字段的最高安全精度选择器

**涉及文件或模块：**

- 修改：`backend/app/parsers.py`
- 测试：`backend/tests/test_smoke.py`

**接口与产出：**

建议新增内部接口：

```python
_serialize_modeling_arrays(
    arrays: list[np.ndarray],
    field_name: str,
    source_names: list[str],
    max_decimal_places: int = MAX_OUTPUT_DECIMAL_PLACES,
) -> BatchSerializationResult
```

返回同一精度下每个数组的量化值和 JSON，以及 `decimal_places`、`max_characters`、最长字段所属样本名。

**实施内容：**

1. 校验数组与样本名数量相同且非空。
2. 按 `5, 4, 3, 2, 1, 0` 依次调用任务 1 的指定精度函数。
3. 只有在本批次所有数组都满足字符限制且没有有效变化丢失时接受候选；第一个可接受值即最高统一精度。
4. 缓存候选结果，最终组装时不重复量化和序列化。
5. 若某精度发生有效变化丢失，记录导致失败的样本和字段；由于更低精度无法恢复变化，可以结束搜索并返回精度不足错误。
6. 若 0 位仍有字段超限，返回包含最长样本、字段、点数、实际最短字符数和 32767 上限的错误，并继续建议缩小行号/X 轴范围；不得生成任何结果 CSV。

**验收标准：**

- 构造“5 位刚好可用”“5 位超限但 3 位可用”“只有 0 位可用”“0 位仍超限”四类确定性数据，选择结果分别正确。
- 构造批次中只有最后一个样本超限的情况，整个字段统一降低到同一精度。
- `XXX` 与 `Intensity` 可以选择不同精度，互不错误牵连。
- 边界严格按 `<= 32767` 成功、`32768` 失败。

**验证：**

- 使用 monkeypatch 将字符上限临时设为较小值构造快速、可读的精确边界测试；另保留至少一个真实 32767 上限测试，防止测试只验证模拟常量。

## 风险与控制

- **风险：7500 点在 0 位时仍超过上限。** 动态精度不是压缩算法，不能保证任意长度都能成功。控制方式是保留明确失败，并在真实数据验收后决定是否追加降采样或更换存储格式。
- **风险：低精度影响峰形或面积。** 采用最高可用精度、禁止整条曲线失去变化，并通过真实 HPLC 数据记录峰位置、峰高、面积和量化误差；不在没有证据时声称模型完全无损。
- **风险：不同样本量化精度形成建模偏差。** 同一批次同一字段强制使用统一精度。
- **风险：序列化优化改变解析兼容性。** 最终文本保持标准 JSON 数组，使用标准 `json.loads()` 和现有 `load_modeling_csv()` 双重回读验证。
- **风险：API 预览与 CSV 不一致。** 两者复用同一批次序列化结果，不在路由或前端二次四舍五入。
- **风险：旧测试把 9000 点一律视为失败。** 将测试改为基于最终字符数和有效变化的行为断言，不把点数本身当作失败条件。

## 回滚策略

本改动不迁移历史文件、不改变数据库结构，也不改变六列 CSV。若上线后真实数据质量不符合要求，可回滚批次精度选择和前端提示，恢复固定 5 位并对超限数据返回原有 400；已生成的自适应精度 CSV 仍是合法的现有六列格式，可继续由建模加载器读取。

## 明确不在本次范围内

- 不增加自动降采样、插值点数配置或删点逻辑。
- 不改成长表、XLSX、NPZ、Parquet 或 HDF5。
- 不拆分 `XXX_1`、`XXX_2` 等额外列。
- 不改变 HPLC 算法顺序、基线算法、训练模型或数据划分逻辑。
- 不保证任意点数都能通过 Excel 限制；0 位仍超限时继续安全失败。
