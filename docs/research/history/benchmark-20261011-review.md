# 第一轮实验综合复盘：Pro 完整回复后的结论

核对日期：2026-10-11。GPT Pro 原始附件的独立复盘已经结束，完整对话回复已保存；本报告结合其重算结果与本地后续 SVM 原始预测检查。未发送新的追问，未改训练源码和冻结科学协议，未启动下一轮实验。

结论：目前没有证明 LM 选模具有稳定平均优势，但也不足以证明方法无效。汇总数字可重算；已经发现 Valid/Test 预测与评价单位不一致，候选顺序与选择的关联很强，决策输入与请求目的也需要改善。

## 先把概念说明白

- memory 关闭，知识检索关闭；此前五条是静态知识卡，不是本轮积累的记忆，未提供给 LM。
- 三套配置由后端固定表生成，不是 LM 生成或随机采样。默认先执行，其余合法表项补足，按 Valid BA 选优。
- LM 看到所有合法模型的默认参数，没看到 A1 实际三套参数逐项数值。模型说明主要是版本号与预算描述。
- 固定 SVM 来自 15 个开发任务的平均 BA 选择，两档都选到线性 SVM；它是预先选定的固定算法对照。预算三时，各任务仍可按 Valid 选择 C。
- 第一次 LM 请求只决定 model_id；第二次 Finalize 只允许空参数结束，无法改变模型、参数或追加试验。

## A1 的变化如何分解

A0：66.354%；保持 A0 所选模型，仅增加后端候选：69.370%；改成 A1 所选模型：68.756%。所以后端候选增加带来 +3.016 点，重新选模型带来 -0.614 点，净 +2.402 点。A1 并非普遍劣于 A0（57 提高、9 持平、48 降低）；也不能把 A1-A0 当纯 HPO 效果。

## 哪些问题已确认

1. **预测和评价口径。** Valid 使用原生类别、按观测行计算；Test 按真实 Sample_ID 平均概率后判类。全部 5,780 个正式结果的单条测量单位核对中，只有 SVM 有 native/probability 类别差异：345 个运行记录、20,681 条预测。ToeSegmentation2 的 130 条类别全部相反，native BA 62.03%、概率口径 37.97%。
2. **敏感性量化。** 在 109 个单条测量任务中仅替换 SVM 已有原生类别，并同步重算 A 和 R，A0-R0 从 -0.538 变为 -0.269 点，A1-R1 从 -0.131 变为 +0.308 点。这不是新正式成绩，没有重新选 Valid 参数或做新的显著性结论，不能据此宣布 LM 已有提升。
3. **候选顺序的强关联。** 280 对 A0/A1 的 Train 统计与默认参数完全相同，但全部改变排列，221 对改变所选模型。560 次正式请求中 262 次选第一项；LR/RF/XGBoost 任一居首的 171 次全部选中首项。排序在 user 候选列表与 system 枚举中同时出现。因果归因仍需只换排列的诊断；固定字母顺序不自动消除偏置。
4. **接口信息不足。** 输入没有完整模型结构说明、轴/任务语义或三套参数明细；仍展示旧的 8:1:1 配置，与真实可信分区不完全一致。提示重心偏向合法动作和 JSON，不够清楚地要求争取更好泛化表现。
5. **原始格式可靠性。** 630 次选择原始 JSON 全部缺最后外层右括号；209 次结束回复也需要修复。630 次原始 model_id 与最终绑定均一致，暂未发现修复换错模型。不能用流程成功率代替模型原始格式正确率。
6. **结束请求作用有限。** 630 次 Finalize 用了 241,375 token，约总 token 的 17.69%，但当前没有影响建模结果的行动空间。是否改为确定性结束属于后续协议提案。

之前核验通过的含义是冻结规则被执行、记录完整且可重算；没有覆盖 Valid 与 Test 端到端决策语义一致性。现在应补充这个限制，不能以之前核验通过排除所有实现和设计问题。

## 下一轮建议：先做三个小步骤

1. **补齐评价对象核对，再提交统一规则草案。** 比较原生类别、逐行概率类别、逐样本组平均概率；确认每个候选的 Valid 预测是否能恢复，再决定哪些只需重算、哪些确实需要补训练。Valid/Test 必须采用同一套判类、聚合与并列规则，不能按已见 Test 哪个更高来选择口径。
2. **候选顺序诊断：48次选择请求，0次模型训练。** 从开发任务选四个固定上下文（两个13候选、两个7候选），固定预算1，让每个模型轮流居首，共40次；每个上下文额外完全相同请求2次，共8次，检查服务自身稳定性。同时调整 user 列表和 system 枚举。已有开发矩阵可用于分析选择结果。此为待批准诊断版本，不会修改历史选择。
3. **分开测试明确目标与补足客观信息。** 先只明确性能目标；另一个版本再补轴语义、实际评价单位、模型结构和实际候选参数。memory、静态知识、思考模式保持关闭，避免同时改变多个因素。之后才判断是否值得比较更强模型或由 LM 提出三套参数。

这些是建议，不代表已经获准改变冻结协议或已经执行。原始 Test 已经用于定位问题，后续优化需明确开发与新的确认性评测边界。
