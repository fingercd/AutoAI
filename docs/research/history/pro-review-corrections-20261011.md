# 对 GPT Pro 复盘意见的核对

已在原研究对话“评估自动化训练Agent方案”提交资料包；Pro 阅读附件后给出 SVM 补充回复与整体复盘。全文分别保留，下面区分采纳结论与必须纠正的部分。没有据此启动新实验或修改冻结协议。

采纳：

1. Valid 和 Test 必须使用同一套类别判定与 Sample_ID 聚合规则，不能仅改 Test。
2. 首先检查候选顺序与决策输入，暂不接 memory、五条静态知识卡或自主追加训练。
3. 用已有完整矩阵做成本低的诊断，再决定是否需要重训。不能据当前小负差断言 LM 方法无效，也不能用事后替代口径的小正差宣布成功。

对 Pro 回复的纠正：

- 本轮实际三套候选的直接定义在 `benchmark_protocol.py`；普通训练的 `search_policy.py` 不是本轮最终搜索表。
- Pro 用 SVM/PLS/LR 作偏好例子不够准确：实际四大偏好是 LR、RF、XGBoost、SVM；PLS-DA 在正式 280 轮里 A0/A1 仅选 1/4 次。
- A1-A0 不是纯搜索收益，因为 221/280 轮改变了选中模型。已有精确分解是：固定 A0 模型，仅增加后端候选 +3.016 点；再切换成 A1 模型 -0.614 点；合计 +2.402 点。
- “重新生成 Valid/Test 即可，不用训练”不能作为承诺。改变 Valid 的指标可能改变候选赢家与最终模型；必须先确认各候选的逐样本 Valid 预测和所需最终模型能否恢复。缺少这些产物时，只能保留敏感性结果，并在获批后补必要训练。
- 不能因发现评估口径问题就排除模型能力问题。模型能力、提示词、证据不足和顺序影响仍需受控诊断区分。
- Pro 首次建议把单条 native predict 和重复测量 probability mean 混用，表述不完整；已追问，后续回复明确改为 Valid/Test 同一端到端聚合规则，并把两种统一方案列为待人类选择的提案。

本次新补查已覆盖全部 5,780 条正式模型结果：单条记录对应一个 Sample_ID 的单位中，SVM 共 345 个运行记录、20,681 条预测出现 native/probability 类别不一致；其余 12 个模型为零。该检查没有把重复测量的行级结果冒充组级结果，重复组的 Valid/Test 聚合问题需要另外按统一规则处理。

建议下一步顺序（提案，不代表已批准执行）：

1. **先确定一致的评价规则并盘点可恢复产物。** 两种可讨论方案：native 类别 + 固定多数票/并列规则；或者各模型概率 + 同组平均 + argmax。两边必须同时用于 Valid 和 Test。不能按哪个方案让 LM 成绩更好来选。
2. **只改变候选顺序的决策诊断。** 保持同一数据证据、默认参数、提示词和预算，对开发任务做原顺序/规范模型 ID 顺序/固定随机顺序比较，记录选择一致率；使用已有模型矩阵评价，不必因此重训。需要先批准诊断版本，不能改旧冻结请求。
3. **比较明确性能目标与补全输入后的决策。** 与上一项分开，明确“争取更高泛化 BA”，提供模型适用性简述和真实三套参数，先不启用 memory 或静态知识。若仍无改善，才用同输入比较推理配置或更强 LM。

全部 114 项正式 Test 已用于本次问题定位，后续据此调整方案时应作为已见诊断资料。确认性评价需明确新的数据边界，不能把反复根据这些 Test 改出的结果继续称为未见评测。
