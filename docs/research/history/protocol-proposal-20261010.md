## 研究目标与推进顺序

研究问题是：在独立样本少、特征维数高的分类任务中，LM 能否根据训练数据证据，以较少训练次数选出合适模型与处理方案；固定容量经验及后续反馈能否进一步改善未见任务的决策。

先完成评测基础、第一次选择请求的验收和开发任务结果矩阵，再做正式比较；之后开展分模型固定容量记忆、少量反馈行动、外部完整建模 Agent 对比。当前主线同一 Session 只执行一个 Run；诊断生成只读建议，不自动追加训练。

## 拟采用的数据使用规则

- 有可靠官方 Test 的任务：保留 Test；从官方训练数据中按独立样本组固定划出约 20% 做 Valid，其余做 Train。所有候选共享这份 Valid，不针对每套参数重新划分。
- 没有官方 Test 的任务：将独立样本分成五组，依次留一组作 Test，另外四组用于本轮建模；再从本轮建模数据中固定划出约 20% 做 Valid。每一轮重新生成 Train 证据、请求 LM 并完成整个训练流程。五轮后合并每个样本在未参与建模时得到的预测，计算任务结果。
- Sample_ID 相同的重复测量始终一起划分。若少数类别无法使 Train、Valid、Test 都类别完整，先按固定 seed 检查三组轮流测试是否可行；仍不可行则记录原因并排除出主结果。不根据成绩挑 seed。
- 固定 split/training/search seed 为 42。主结果使用 balanced accuracy，辅助指标为 macro F1、accuracy；同时报告时间、实际模型训练次数、LM 请求与 token。
- 用于 LM 选方案的摘要只来自 Train；参数比较与早停只使用 Valid；Test 只用于报告本轮最终结果。归一化与特征变换从当前允许的训练数据学习参数。
- 开发任务与锁定评测任务按原始任务家族分开；主评测记忆关闭，不跨测试轮次更新经验。重复测量以独立样本平均类别概率后计算主指标。

这里的五组轮流测试用于减少单次 Test 太小带来的偶然性；每套参数仍只在同一份固定 Valid 上比较一次。

## 拟采用的比较组和有限参数尝试

先固定处理方案，比较 R0（随机选合法模型、默认参数）和 A0（LM 选合法模型、同一默认参数）；增加从开发任务确定并冻结的强固定模型，及依据 Valid 从多模型结果中选择的参考方法。多模型参考方法单独报告完整计算成本。

补充比较 R1（随机选模型、最多三套参数）和 A1（LM 选模型、相同最多三套参数）。默认配置算一套；不对每套配置再次重复划分。暂不把现有枚举、Random Search、TPE 三种搜索器对比及六套预算列为第一轮必做。该收缩是提案，尚未获批。

三套参数需在运行前逐模型冻结。建议候选如下；所有其他参数保持既有默认值：

| 模型 | 拟尝试的关键参数 |
|---|---|
| PLS-DA | 成分数 1、3、5 |
| PCA-LDA | PCA 成分数 3、10、30 |
| Logistic regression | C 为 0.1、1、10 |
| 线性 SVM | C 为 0.1、1、10 |
| Random forest | max_depth 为 3、5、10；min_samples_leaf=2、max_features=sqrt |
| XGBoost | max_depth 为 2、3、5；n_estimators=100、min_child_weight=3 |
| 已实现深度模型 | learning_rate 为 0.0003、0.001、0.003；weight_decay=0.0001 |

成分数按 Train 样本数与维数过滤非法值；维度相关默认值沿用现有明确规则，最终合法列表在 LM 选择之前冻结。有效候选少于三套时使用真实数量，不通过重复相同配置凑数。不能直接取现有顺序前三套来代替这份待确认列表。

所有比较组共用同一合法模型集合、参数列表、数据划分和训练实现。候选比较拟统一使用 Valid balanced accuracy；深度模型每套候选内部仍按最低 Valid loss 保存权重，再以该权重的 Valid balanced accuracy 比较候选。当前随机森林按 OOB、深度模型按 Valid loss 选优的原生行为，需要在隔离评测适配中明确处理，不静默改普通训练入口。

第二阶段再打开当前已有的动态处理方案：LM 同时选模型及合法的归一化/类别平衡组合；随机基线先等概率抽模型，再等概率抽该模型合法配方。第一阶段不扩展 LM 自由生成参数的能力。

## HPO 预算与最终训练

参数尝试预算 B 表示：一个任务的一轮评测中，所选模型最多尝试 B 套不同超参数。它不表示模型数量、epoch、Test 次数、LM 请求次数或整项任务的总运行时间。

当前代码 `fixed` 使用一套；`bounded` 默认六套，`max_trials` 可明确设为三，范围 1 至 18，真实套数还受合法候选数量限制。当前默认不能据此宣称已改为三套。

传统模型最多三套通常对应三次候选训练，加一次最终训练。最终训练即 refit：锁定参数后，将 Train 与 Valid 合并，从头重新学习归一化、模型内部变换和模型权重，随后只用独立 Test 评测。固定参数路径仍保留既有候选验证与最终训练流程。Test 不参与合并。

当前深度模型保留 Train 训练期间 Valid loss 最低的 checkpoint，不额外进行 Train+Valid 重新训练。因此最多三套对应最多三次模型训练；每次最多 200 epochs 是另一个预算，真实 epochs、用时单独记录。

## 第一次 LM 请求具体做什么

程序先读 CSV、验证分组与格式、固定 Train/Valid/Test，生成 Train-only 统计与风险，并依据数据维度及环境能力列出合法模型/配方。LM 看到摘要、候选和绑定标识，选择一个允许的方案；不会收到整个矩阵，也不会看到 Test 成绩。

请求由规则文本与 JSON 格式的上下文组成，JSON 的字段名、括号和值一起作为消息正文发送。响应中的 recipe_id 解析成已冻结的执行配置；structured_config 也必须匹配合法成员，不能任意编造参数。程序校验后提交 queued Run，worker 实际训练；LM 自己不运行分类器。

验收包括：上下文无 Test、响应合法、接受的提案与最终实际配置一致、试参数次数正确、时间/token 有记录、恢复不重复提交、结束请求绑定实际 Run。之后用 R0/A0 和 R1/A1、固定模型检验选择是否有效。合法返回只能证明接口功能，不能证明选择更优。

主比较拟关闭知识、经验记忆和反馈诊断，采用选择与结束两次正常 LM 请求；诊断另作功能验收。当前普通新任务的反馈诊断默认开启，这里是拟议评测配置，不是修改系统默认值。

## 论文依据及适用边界

- [RamanBench](https://arxiv.org/html/2605.02003)，2026-10-07 v3，采用固定模型参数、80/20 Train/Test、三个随机 seed；单独提供 AutoGluon 四小时预算。它支持固定参数评测的可行性，但包含多种样本规模，不能作为所有小样本任务只需固定参数的证明。
- [PMLBmini](https://arxiv.org/html/2409.01635)，2024，逻辑回归只比较四个 L2 参数，并独立评价结果。它支持小参数表的合理性，不证明恰好三套适合所有模型。
- [高维转录组评测方法论文](https://www.pure.ed.ac.uk/ws/portalfiles/portal/345618345/OP_BIOA230054_1..5_vbad048.pdf)，2023，展示用于选参数的成绩可能偏高，强调在独立数据上评价以及在允许的训练数据中进行特征筛选。我们据此保留选择与最终测试的边界。

最多三套是基于本项目贡献重点和计算预算提出的工程选择，不是文献统一标准。强预测器、完整非 LM AutoML 和外部建模 Agent 对比在第一轮机制证据之后安排，具体实现与预算再确认。
